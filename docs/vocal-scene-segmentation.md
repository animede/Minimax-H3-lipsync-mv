# ボーカルのシーン分割仕様

## 目的

MiniMax-H3へ渡す各クリップを5～10秒に収めながら、歌唱中の単語や音節の途中を
できるだけ避け、無音、声量の谷、ブレス、楽曲構造などの自然な位置で映像を切り替える。

この処理は歌詞、文字起こし、音声理解LLMを使用しない。分離ボーカルと入力原曲から
得られる音響特徴だけを使う。また、候補位置ごとの根拠とスコアをJSONへ残し、結果を
検証できるようにする。

実装は主に `app/services/audio.py` の `analyze_boundaries()`、`plan_scenes()`、
`quantize_scene_plan()` にある。

## 処理の全体像

```text
入力原曲
  ├─ Demucsでボーカルを分離 ──> vocals.wav
  │                                 │
  │                                 ├─ 音量の局所最小
  │                                 └─ ブレス候補
  └─ 原曲を解析
                                    ├─ ビート・小節候補
                                    └─ クロマ変化
                                             │
                                             v
                                      境界候補を統合・採点
                                             │
                                             v
                                  動的計画法で5～10秒に分割
                                             │
                                             v
                                    24fpsのフレームへ量子化
```

## 1. ボーカル分離

Stem APIへ入力原曲を送り、ボーカルStemを取得する。サービスが利用できない場合は、
ローカルのDemucs `htdemucs`へフォールバックする。以降の歌唱音量とブレスの解析には
分離後の `vocals.wav` を使い、ビートと楽曲構造の解析には入力原曲を使う。

## 2. 解析単位

原曲と分離ボーカルを16kHz、モノラルで読み込む。解析のhop lengthは1,600サンプル、
すなわち100msである。ボーカルから次の特徴量を計算する。

- RMS音量（曲中の最大値を基準にしたdB）
- スペクトル平坦度
- ゼロ交差率（ZCR）

原曲からはビート時刻とクロマ特徴量を計算する。

## 3. 境界候補とスコア

### ボーカル音量の谷

RMS音量が前後200msの範囲で局所最小になる点を調べ、音量に応じて採点する。
曲の先頭・末尾から0.5秒以内は候補にしない。

| 条件 | 種別 | スコア |
|---|---|---:|
| −38dB以下 | `silence` | 100 |
| −28dB以下 | `vocal_valley` | 68 |
| −20dB以下 | `soft_valley` | 36 |

無音に近いほど、単語の途中ではない可能性が高いとみなす。

### ブレス候補

次の条件をすべて満たすフレームを `breath` として42点にする。

- ボーカル音量が−38dBより大きく−15dB未満
- スペクトル平坦度が曲内の72パーセンタイル以上
- ゼロ交差率が0.08以上

ブレスは広帯域かつ無声音になりやすい性質を利用した補助的な推定であり、音声認識による
ブレス判定ではない。

### ビートと小節

Librosaで原曲のビートを推定する。4拍子を仮定して、検出されたビート列の4拍ごとの点を
小節候補として扱う。

| 種別 | スコア |
|---|---:|
| `bar`（4拍ごと） | 26 |
| `beat` | 10 |

拍子を自動判別しているわけではないため、3拍子や変拍子では `bar` は厳密な小節頭を
表さない。

### セクション変化

原曲のクロマ特徴量について隣接フレーム間の差を取り、変化量が曲内の上位10%に入る
局所ピークを `section_change` として46点にする。これはコード感や音楽構造が大きく
変わる位置の候補であり、Aメロ、サビなどのラベルを分類する処理ではない。

### フォールバック候補

自然な候補が不足していても5～10秒の制約内で曲全体を分割できるよう、0.25秒間隔で
`fallback` 候補を置く。スコアは0点なので、自然な候補と競合する場合は原則として
選ばれない。

## 4. 近接候補の統合

0.22秒以内にある候補を同じ境界として統合する。統合後の時刻はスコアを重みにした
加重平均、スコアは各候補の合計になる。種別も `silence+bar` のように結合するため、
複数の音響的根拠が重なる位置ほど選ばれやすい。

シーン計画へ曲の先頭と末尾を加えた後は、丸め誤差による重複を避けるため0.08秒以内の
候補をもう一度統合する。

## 5. 動的計画法による分割

候補を時刻順に並べ、曲頭から曲末までの最適経路を動的計画法で求める。隣接する境界間、
つまり1シーンの長さには次の制約を設ける。

- 最短: 5秒
- 目標: 9秒
- 最長: 10秒

各境界へ到達したときの評価値は次の考え方で計算する。

```text
評価値 += 境界スコア
          - |シーン長 - 9秒| * 5
          - 7秒未満の追加ペナルティ
          - シーン追加コスト 18

7秒未満の追加ペナルティ = (7秒 - シーン長) * 9
```

曲末には境界スコアを加えない。シーン追加コストによって、不必要に短いシーンを多数作る
構成を避ける。この結果、通常は7～10秒程度を優先しつつ、強い無音や複数の根拠が重なる
場合は5秒までの短いシーンも選択できる。

曲全体が5秒以下の場合は分割せず、実尺の1シーンとして扱う。H3へ音声を渡す段階でのみ、
必要に応じて末尾を無音で5秒までパディングする。

## 6. 歌唱比率

選択された各シーンについて、100msごとのボーカルRMSが−35dBを上回るフレームの割合を
`vocal_ratio` として記録する。

```text
vocal_ratio = シーン内でボーカルRMS > -35dBとなるフレーム数
              / シーン内の全フレーム数
```

`vocal_ratio >= 0.35` のシーンはプロンプト生成時に歌唱シーンとして扱う。正面または
3/4向きのmedium close-up、隠れていない口元、入力ボーカルへの明示的なリップシンクを
強制する。0.35未満では非歌唱区間として、口を自然に閉じる指示を加える。

この比率は境界そのものの選択には使わず、境界決定後の演出制御に使う。

## 7. フレーム量子化

秒単位で確定した全境界を24fpsの共通フレームグリッドへ丸める。各シーンの尺を個別に
丸めるのではなく、境界時刻を先にフレーム番号へ変換して隣接差を取る。これにより、
シーン数が増えても丸め誤差が累積せず、最終フレームが楽曲末尾と一致する。

FPSは `app/config.py` の設定値を使用する。

## 8. 解析結果

各ジョブの `analysis/` 以下へ次のファイルを保存する。

### `boundary_analysis.json`

- 楽曲の長さ
- 推定テンポ
- 解析窓の間隔
- ボーカルRMS系列
- 統合後の全境界候補
- 各候補の時刻、種別、スコア、補助特徴量

### `scene_plan.json`

各シーンについて次の情報を保存する。

- `start` / `end` / `duration`
- `start_frame` / `end_frame` / `frame_count`
- `vocal_ratio`
- 選択された末尾境界の `boundary_kind`
- 選択された末尾境界の `boundary_score`

たとえば `boundary_kind` が `bar+silence` なら、そのシーンは小節候補と無音候補が
重なった位置で終了したことを示す。

## 制約と意図

- 歌詞や音素を認識しないため、「単語の終端」を直接検出しているわけではない。
- `breath` と `section_change` は音響特徴に基づく候補であり、意味的な分類結果ではない。
- `bar` は4拍ごとの簡易推定である。
- それでも、固定長の均等分割より無音や声量の谷を優先し、すべての判断根拠をJSONで
  確認できることを重視している。

## 関連する設定

`app/config.py` の次の値でシーン長を変更できる。

```python
min_scene_seconds = 5.0
target_scene_seconds = 9.0
max_scene_seconds = 10.0
```

閾値や候補スコアは現在 `app/services/audio.py` に定数として実装されている。変更時は
`tests/test_scene_planner.py` の全曲カバー、尺制約、自然境界の優先、フレーム累積誤差の
テストも合わせて確認する。

# V3への適用と訂正（2026-08-29、原本: Minimax-H3-lipsync-mv）

本書の仕様はV3の `music_analysis.py`（`plan_scenes_dp()` ほか）へ移植済み。
V3実装は以下の点で原本仕様から**意図的に乖離**している。

## V3での変更点

1. **beat / bar / section_changeのうちbeat/barは不採用**（Librosa依存排除）。
   同一曲A/Bでbeat/barの排他的貢献はゼロ、完成MVのカット-ビート距離は
   偶然水準（120bpmで中央値0.167秒）だったため。section_changeはNumPyの
   スペクトラルフラックスで代替実装（器楽区間限定）。
2. **phrase_end候補（スコア85）を追加**。原本の目的「音節の途中を避け」は、
   100msホップ解析では短いフレーズ末尾の間隙を取りこぼすことがある。V3は10msホップの
   相対急落検出（200ms以内に9dB以上下降、ピーク相対RMSが−15dB以下、±100msで極小）
   を使用し、較正対象8点をすべて±0.15秒以内で検出した。なお、較正資料に記録された
   −26〜−48dBはV3のピーク相対dBと基準が異なるため、絶対値をそのまま流用していない。
3. **器楽区間の「無音の壁」間引き**: ボーカルStemの器楽区間は全面が
   スコア100のsilence候補になり「カット追加が常に得」の経済で乱切りされる
   （原本サンプルでもイントロ平均6.3秒 < target 9）。V3は3秒超の無音連続区間の
   内部候補を端点のみに間引く。
4. **min/max/targetは呼び出し側パラメータ**（原本は5/9/10固定）。
   H3の解像度別品質キャップ（768×448→8秒 / 1024×768→10秒）に連動し、
   窓幅が4秒未満のときのみminを `max × 0.8` へ引き上げる。

## 原本仕様への注記（V3でも共通の既知限界）

- **窓幾何による強制カット**: 高スコア候補同士の間隔がmaxを超えると、DPは
  候補を素通りして中間の弱い点で切らざるを得ない（実測例: 候補間隔13.9秒 >
  max 10秒 → 歌唱途中カット）。検出の問題ではなく制約幾何の問題で、
  maxを上げる（品質検証とセット）以外の解はない。
- **dBは曲中最大値基準（ピーク相対）**。絶対dBFSと誤認して閾値を流用すると
  再較正が必要になる（V3移植時に実際に発生）。
